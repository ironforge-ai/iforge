# The public environment contract -- phase 03.1 (clawdi -> iforge), plan 06.
#
# GENERATED ONCE from the pre-rename tree, then FROZEN. After plan 06 lands, the seven
# membership sources below no longer carry the old spellings, so regenerating would find
# nothing: this file IS the contract from here on, the same authority idiom as
# config/postgres-image.txt.
#
# GRAMMAR: one `IFORGE_<NAME>=CLAWDI_<NAME>` pair per line, sorted. Blank lines and lines
# whose first character is `#` are skipped.
#
# `IFORGE_<NAME>` is the ONLY spelling a user may set (D-05a). `CLAWDI_<NAME>` is the
# internal register the alias copies into; it is never documented and never read from the
# user. Both implementations of the boundary are asserted equal to this file by tests:
#   packages/cli/src/lib/brand-env.ts   (brand-env.test.ts, contract-parity test)
#   backend/app/core/brand_env.py       (backend/tests/test_brand_env.py, parity test)
#
# MEMBERSHIP RULE (D-05a in machine form). A `CLAWDI_<NAME>` is public -- and therefore has a
# line here -- if and only if it appeared in at least one of:
#   1. any `*.env.example`
#   2. any `docker-compose*.yml`
#   3. any `config/*.yml`
#   4. anything under `deploy/**`
#   5. `install.sh`
#   6. the `Environment:` block of `addHelpText` in `packages/cli/src/index.ts`
#   7. any `*.md` outside `.planning/`
#
# EXCLUSIONS applied to that union, each with its reason:
#   - `VITE_CLAWDI_*` (4 keys). Vite substitutes `import.meta.env.X` at build time, so no
#     runtime alias can reach them. Plan 07 owns all four keys and all their read sites, and
#     records the four pairs in the WEB BUILD-TIME KEYS section at the foot of this file --
#     fenced behind `#` so neither alias parser can pick them up.
#   - the four dynamic prefixes `CLAWDI_`, `CLAWDI_PROVIDER_`, `CLAWDI_EGRESS_` and
#     `CLAWDI_CHANNEL_`. These construct variable names at runtime; they are not variables.
#   - `CLAWDI_HOME` (D-07 / X-1) and `CLAWDI_RUNTIME_USER` (D-07 / X-4). Both are durable
#     entries in config/rebrand-allowlist.txt: the `~/.clawdi` state root and the runtime OS
#     user are a migration, not a sweep, and are deferred out of this phase.
#   - `CLAWDI_WA_EGRESS`. Measured, not assumed: `config/deploy.yml:168` reads
#     `chain=CLAWDI_WA_EGRESS` -- it is the NAME OF AN IPTABLES CHAIN created in the host's
#     OUTPUT table and asserted by `scripts/deploy-whatsapp-sidecar.sh:196-198`, not an
#     environment variable. It entered the candidate union only because membership source 3
#     is a file-level grep. Renaming it would orphan a live chain.
#   - the test-runner plumbing under `scripts/`: `CLAWDI_REPO_SOURCE`, `CLAWDI_TEST_WORKDIR`,
#     `CLAWDI_TEST_RUNNER_SKIP_BUILD`, `CLAWDI_TEST_COMPOSE_PROJECT_NAME` and
#     `CLAWDI_TEST_DB_WAIT_SECONDS`. Recorded by plan 08 as an EXCLUSION rather than left as
#     an omission (WINDOWS #29), because `scripts/` sits outside the residual scanner's
#     pathspec, so a green scan says nothing about it and the completeness claim above needed
#     backing. None appears in any of the seven membership sources: `scripts/test.sh` sets
#     them for itself and for the container it launches, and no user sets one. They are the
#     same C-13 internal-plumbing class as `CLAWDI_NATIVE_BINARY`, which the allowlist already
#     names. `scripts/check_rebrand_residual.py` records the same decision in machine form, in
#     its `OUT_OF_SCOPE` entry for `scripts`.
