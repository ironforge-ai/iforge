# Rebrand do-not-rename allowlist -- phase 03.1 (clawdi -> iforge).
#
# This file is the durable authority for where the rebrand boundary sits. Both
# scripts/check_rebrand_carveouts.py and scripts/check_rebrand_residual.py read it, and
# scripts/test.sh runs both on the host before the Docker build, so a corrupted sweep fails in
# seconds rather than after a 10-15 minute suite.
#
# It lives in config/ rather than under .planning/ deliberately: /gsd-cleanup archives
# .planning/phases/ when a milestone completes, and a `bun run test` that breaks on planning
# maintenance is not a guard. config/postgres-image.txt is the same idiom -- a plain text file
# that is the single authority a committed checker validates against.
#
# GRAMMAR, one entry per line:
#   empty line, or first non-space character is `#`   -> skipped
#   path:<fnmatch glob>   -> allowed if the hit's repository-relative PATH matches the glob
#   re:<python regex>     -> allowed if re.search matches `<path>:<line>:<text>`
#   anything else         -> fixed substring, matched against `<path>:<line>:<text>`
#
# An entry is removed only by a plan that also proves the corresponding surface is clean.
# Through phase 03.1 this file also carried a staging section at its foot naming the plan that
# removed each of its entries; plan 08 emptied it. Every entry sits in a section whose comments
# cite the carve-out id (C-n), deferral id (X-n) or project-rule id (P-n) that keeps it -- an
# exemption with no citation is indistinguishable from a bug, and
# backend/tests/test_rebrand_guards.py asserts the citation.
#
# CLASSIFICATION, one declaration per scope, added by plan 11 and machine-checked. A scope
# declares either that its fence is PERMANENT -- a carve-out never expected to move -- or that
# it is DEFERRED, followed by an arrow and the phase that will move it. The exact spelling of
# both declarations is `_CLASSIFICATION_MARKERS` in scripts/check_rebrand_residual.py, and any
# section below shows the real form; it is deliberately NOT written out here, because the
# declarations are meant to be greppable and a worked example in a header would answer that
# grep with a line that fences nothing. `test_every_declaration_in_the_real_allowlist_governs_
# at_least_one_entry` holds that property.
#
# A citation answers "which decision keeps this entry". It could not answer the question phase
# 03.1 verification found unanswered: whether a fence holds a carve-out or an unfixed defect.
# Three entries here were MEASURED to be fencing defects -- documented commands that no longer
# resolve, and a wire-key regex that incidentally covers rendered support text -- and nothing
# in the grammar could tell them from the carve-outs beside them. So the earlier claim that
# this file "holds permanent carve-outs only" was false, and the declarations now say which is
# which: 43 permanent, 5 deferred, of the 48 scopes that hold entries (132 entries). Plan 11
# measured 29 / 16 of 45; plan 03.3-14 re-declared the whole 03.3 deferral set and split one
# scope; plan 03.3-24 retired one scope and re-declared two, which is where the difference comes
# from. Do not hand-count these -- derive them, as
# `test_every_declaration_in_the_real_allowlist_governs_at_least_one_entry` does.
#
# A declaration governs the entries beneath it until the next blank-line-separated comment run
# or the next section banner, whichever comes first. That is the granularity this file already
# writes in -- its two largest sections are umbrellas over sub-blocks that each carry their own
# citation and each belong to a different class. `unclassified_sections` in
# scripts/check_rebrand_residual.py reports any scope that fences without declaring, and any
# deferral with nothing after its arrow: a deferral that names nobody reads as a decision while
# committing nobody to carry it out, which is exactly how a fence over a defect survives.
#
# Fencing an unfixed defect is LEGAL here. Fencing one silently is not. And a fence is never
# retracted before the fix it was hiding lands (D-10) -- the three `DEFERRED -> 03.1-13`
# scopes below stay exactly as they are until plan 13 fixes the lines and retracts them in the
# same wave, because removing a fence without fixing the line underneath only turns the guard
# red. `TBD-brand-migration` is a PLACEHOLDER with a scheduled substitution, not a blank: plan
# 03.1-15 creates the receiving phase and replaces the token here and at
# packages/cli/tests/cli-help-brand-contract.test.ts:139 in one pass. Do not invent a phase
# number.
#
# WHY SOME DEFERRALS NOW NAME A LEDGER ENTRY RATHER THAN A PHASE, recorded by plan 03.3-14 so
# the next reader inherits the reasoning instead of re-deriving it. That plan was written to
# RETIRE the fifteen scopes deferred to phase 03.3, on the premise that once the phase's other
# thirteen plans landed those entries would cover nothing. Measured on 2026-09-10 against the
# finished tree, the premise was wrong: the fifteen scopes held 65 entries covering 304 hits, of
# which 225 were fenced by nothing else. Retiring them would have failed the residual scanner
# with 225 real findings -- "removing a fence without fixing the line underneath", four
# paragraphs up, exactly.
#
# So the entries stayed and the DECLARATIONS moved, which is the only half that had actually
# expired. Eight scopes became permanent, because P33-21, P33-06, D-07 and the A-P1 host-path
# ruling had by then decided the identity stays: it lives on a provisioned server or on the
# wire, outside the coexistence rationale that motivates every other move in this set. Seven
# still fence measured, unfixed defects, and those may not be re-declared permanent -- a
# permanent declaration over a known defect is the silent fence this whole classification rule
# exists to catch, reintroduced one level up. They needed an owner, and no phase existed to
# name. The broken-windows ledger is that owner: `/gsd-ship` blocks while an entry is open, so
# a ledger id commits more than a phase number does, and naming one invents nothing. Each such
# scope's prose enumerates by file and line what it now holds. A future phase that adopts one of
# these classes should replace the ledger reference with its own number, in the same change that
# fixes the lines -- and then retire the scope, which is what this plan could not do.
#
# WHAT PLAN 03.3-24 DID WITH THE EIGHT SCOPES 03.3-14 LEFT, measured 2026-09-11 against the tree
# after the nine gap-closure plans of waves 1-3 merged. Each scope's coverage was counted, and its
# SOLE-FENCE count taken by deleting its entries from a scratch copy of this file and running
# scripts/check_rebrand_residual.py against that copy -- never by reading a regex, because reading
# one cannot tell a hit fenced twice from a hit fenced once.
#   ONE RETIRED. The published-package-identity scope (package/clawdi, npm/v/clawdi,
#     npm i -g clawdi, bun add -g clawdi) covered 2 hits when 03.3-14 measured it and covers 0
#     now: plan 03.3-19 moved README.md:8 and :18 onto https://www.npmjs.com/package/@iforge/cli.
#     Both halves of the retirement test held -- nothing else was fencing those lines, and the
#     lines are right -- so entries and prose went together in one commit (D-10). What now holds
#     the property is backend/tests/test_readme_identity_contract.py, which fails with the line
#     number if README ever names a published package other than this fork's own.
#   TWO RE-DECLARED PERMANENT. Both X-2 scopes -- the concrete hosted unit names, and the
#     `clawdi-*` naming rule as documentation states it. The authority arrived after 03.3-14:
#     P33-21 was amended on 2026-09-10 and REQUIREMENTS.md MIGR-01 now names
#     clawdi-runtime-watch, clawdi-daemon and clawdi-runtime-sidecar as hosted identities only an
#     operator procedure moves, in the same breath as the hosted roots and the runtime OS user
#     that 03.3-14 had already made permanent here.
#   FIVE STILL DEFERRED, each because a line underneath it is still wrong. Two of those five --
#     the clawdi.ai domains and the .env.clawdi example filename -- have a sole-fence count of
#     ZERO and are kept anyway. That is the trap this file has now caught twice: the narrowed C-4
#     wire-key regex independently covers both, so retiring either measures clean while filing
#     real documentation defects under a PERMANENT declaration that calls them protocol
#     identifiers. A sole-fence of 0 is necessary for retirement and has never been sufficient.
#
# AND ONE CORRECTION A READER NEEDS BEFORE TRUSTING ANY DEFERRAL BELOW. Every ledger id 03.3-14
# wrote into this file named an entry ONE LOWER than the one it meant, and plan 03.3-24 corrected
# all four by matching each entry's text to the defect the scope describes: the state root moved
# #109 -> #110, the clawdi.ai domains #110 -> #111, and both the example dotenv filename and the
# backticked identifier #111 -> #112. (#109 is 03.3-14's own measurement record, which is why the
# chain shifted.) The X-2 and X-3 scopes name #102 and #94 and were already right. A deferral
# pointing at the wrong entry passes every gate in this repository -- `unclassified_sections`
# checks only that SOMETHING follows the arrow -- and reads as a decision while committing
# nobody, which is the failure that check exists to prevent, one level in.
#
# Do not reintroduce a staging section: `load_allowlist` in scripts/check_rebrand_residual.py
# now refuses to parse an entry whose section carries the marker that section used, so a
# temporary exemption cannot outlive the plan that added it. Read that function's docstring
# before adding one. Growing this file to silence a finding is the failure mode T-03.1-05
# names -- if a hit belongs to no carve-out class and no later plan, it is a real finding and
# belongs in a plan summary, not here.
